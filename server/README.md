# AI Mental Health Support & Blood Test Analysis — backend

Small Express API that proxies two features to the Gemini API:
the AI Mental Health Support chat (الاستشارات الطبية → مساعد الصحة النفسية
الذكي) and the AI Blood Test Analysis card (التحاليل والفحوصات). Exists
because the API key must never be embedded in frontend JavaScript.

See [SECURITY.md](../SECURITY.md) § 5 for the design rationale.

## Setup

```bash
cd server
npm install
cp .env.example .env
# then edit .env: set GEMINI_API_KEY (get one at https://aistudio.google.com/apikey)
npm start
```

Server listens on `http://localhost:8787` by default and only accepts
requests from `FRONTEND_ORIGIN` (default `http://localhost:8080`, matching
`serve.ps1` in the project root).

## What it does

- `GET /api/csrf-token` — issues a CSRF token (HttpOnly cookie + JSON body).
- `POST /api/ai-chat` — `{ sessionToken, message, lang }` →
  `{ reply, escalated }`. Requires:
  - `X-CSRF-Token` header matching the `csrf_token` cookie
  - a valid anonymous `sessionToken` (format `anon_<digits>`, as generated by
    `Security.getAnonymousSessionToken()` in the frontend)
  - passes a per-session token-bucket rate limit (~1 msg/5s sustained, burst 8)
- Runs a crisis-keyword check (`src/security.js#detectCrisis`) before ever
  calling the model. On a match, it returns a fixed, warm safety message —
  pointing to the app's own Emergency SOS, a trusted person, and local
  emergency numbers — and logs an escalation, **without** sending that
  message to the model.
- Otherwise calls `gemini-3.6-flash` with a system instruction (`src/aiChat.js`)
  that keeps the assistant supportive-listening only (no diagnosis, no
  medication advice) and instructs it to redirect toward real help on any
  risk signal, even ones the keyword net missed.
- Logs every turn to `server/data/ai-chat-transcripts.jsonl`, keyed only by
  the anonymous session token (never a name or patient ID) — and
  escalations separately to `server/data/escalations.jsonl`. Both are
  git-ignored; in production these become an actual anonymized-transcript
  store and a real on-call paging integration, respectively.
- `POST /api/labs-analysis` — `{ sessionToken, panel, lang }` →
  `{ summary, recommendations }`. Same CSRF/session-token requirements as
  `/api/ai-chat`, plus its own stricter rate limit (~1 request/20s, burst 3
  — this is a heavier action than a chat message). `panel` is a small array
  of `{ name, value, unit, range, flag }` biomarker readings (no patient
  name/ID) — validated by `isValidPanel()` in `src/security.js`. Calls
  `gemini-3.6-flash` (`src/labsAnalysis.js`) with a system instruction that
  explains flagged markers in plain language, explicitly avoids diagnosing
  or recommending medication, and constrains the response to a
  `{ summary, recommendations[] }` JSON shape via Gemini's `responseSchema`
  (parsed defensively regardless — falls back to a generic message if
  the model ever returns something unexpected). Logs each analysis to
  `server/data/labs-analysis.jsonl` (also git-ignored), keyed only by the
  anonymous session token.

## Wiring it to the frontend

[js/app.js](../js/app.js)'s `wireAIChat()` and `wireBloodPanelAnalysis()`
already call this API — point `AI_CHAT_BASE_URL` near the top of that file
at wherever this server actually runs. If the backend isn't reachable,
both features show a clear inline error instead of failing silently.

## Not done here (see SECURITY.md)

Real user auth, PHI storage, HIPAA/NDMO-PDPL audit logging, and the actual
on-call escalation integration are out of scope for this starter — this repo
is the frontend deliverable, so this backend is intentionally minimal:
enough to make the AI chat feature real and safe, not a full hospital
backend.
